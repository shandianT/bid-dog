# 中标狗 · 云端网页版部署指南

给客户/同事发一个网址就能用,无需安装。适合验证功能逻辑、给客户演示、小范围试用。

## 一、最快路径:一台云服务器 + Docker(15 分钟)

任意 2 核 4G 云主机(阿里云/腾讯云/华为云均可,按量付费约 ¥0.5/小时),装好 Docker 后:

```bash
git clone https://github.com/shandianT/bid-dog.git && cd bid-dog
export BID_PASSWORD='你自己定的访问口令'      # 必设!公网无口令=谁都能上传下载标书
docker compose -f deploy/docker-compose.yml up -d --build
```

打开 `http://服务器IP:8080` → 输入口令 → 直接用。

> 云主机安全组要放行 8080(或按下面接 HTTPS 后放行 443)。

## 二、加 HTTPS(对外发链接前务必做)

有域名的话最省事的是 Caddy(自动申请证书):

```bash
# 1) docker-compose.yml 里把端口改成只绑本机:  "127.0.0.1:8080:8080"
# 2) 装 Caddy 后写 /etc/caddy/Caddyfile:
标书.你的域名.com {
    reverse_proxy 127.0.0.1:8080
}
# 3) systemctl reload caddy
```

没有域名时,至少确保口令足够复杂,并只发给可信的人。

## 三、这套云端版做了什么隔离

| 机制 | 说明 |
|---|---|
| **口令门** | `BID_PASSWORD` 未通过则任何页面/接口都进不去(401),口令存 30 天 cookie |
| **访客隔离** | `BID_MULTIUSER=1`:每位访客一个独立工作区(`/data/workspaces/<访客ID>/`),任务、素材库、模型配置互不可见——**实测验证过** |
| **锁定生成引擎** | 网页端禁止修改生成引擎命令(否则等于给访客开服务器远程执行);需要时由部署方用 `BID_ALLOW_AGENT_CONFIG=1` 显式开启 |
| **数据持久化** | 任务与素材落在 docker volume `bid-data`,容器重建不丢 |

## 四、云端接真实 AI 生成(可选)

默认是内置演示流程(12 阶段 mock,足够验证交互与功能逻辑)。要在云端产真实标书:

1. 镜像里装好 claude CLI 或 codex 并完成登录(需持久化其配置目录);
2. 解压技能包到 `/data/bid-multiagent-tao`;
3. 起容器时加 `AGENT_CMD` 环境变量(命令模板里可用 `{tender}` `{out}` `{materials}` `{skill}` `{jobid}` 占位符,详见 BUILD.md),或加 `BID_ALLOW_AGENT_CONFIG=1` 后在网页里选——注意后者等于把命令编辑权开给访客,只在可信网络里用。

> 提醒:真实生成会在服务器上跑 agent 并消耗你的模型额度,对外开放前先设好用量上限。

## 五、给试用者的一句话说明

> 打开 `https://你的域名` → 输入口令 → 把招标文件拖进去 → 左侧看进度、中间和 agent 对话、右侧下载产出;
> 「素材库」里可以上传过往标书,系统会自动拆成可复用的章节和图片素材。
> 你的任务和素材只有你自己可见。

## 六、常见问题

- **上传大文件失败**:反向代理默认限制 1MB,Nginx 加 `client_max_body_size 100m;`(Caddy 无此限制)
- **中文 Word 字体**:镜像已装 Noto CJK + 楷体/明体,出件字体正常
- **要几个人同时用**:2 核 4G 可支撑 10~20 人轻量试用;真实 agent 生成是重负载,建议按并发数升配
- **想清空某个访客的数据**:删 `/data/workspaces/<访客ID>/` 即可
