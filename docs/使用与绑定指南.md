# 中标狗 · 使用与绑定指南

> 作者:FDE-家涛

## 一、只看到「演示模式」?

- **旧安装包(约 2MB)是纯界面壳**,不含引擎——只会演示。最新版安装包已内置本地引擎与 OpenCode 执行外壳，双击安装即是完整功能，请到 Release 页重新下载最新包。
- 判断方法:应用左下角显示「**本地引擎 · 已连接**」= 真实模式;右上角黄色「演示模式」标签 = 没连上引擎(刚启动等几秒,或看日志 `~/Documents/中标狗/engine.log`)。

## 二、接入你的模型(senseaudio 已设为默认)

「设置 · 模型接入」里:

1. 名称与网关已默认填好(`senseaudio` / `https://api.senseaudio.cn/v1`),只需**粘贴你的 API Key**
2. 点「**获取模型列表**」→ 自动列出你套餐可用的全部模型(如 `senseaudio-s2`),点模型输入框选择
3. 点「**添加并测试**」→ 会**用所选模型真发一次对话**,显示「✓ 测试通过 · 模型回复"pong"」才算真的可用;失败会显示具体原因(401=Key 错、404=无此模型、超时=网络)

> 安全提醒:API Key 只存本机引擎配置;在聊天/群里发送过的 Key 建议到网关后台轮换一个新的。

## 三、绑定生成引擎(真实标书生成)

「设置 · 模型接入 → 生成引擎」选一个,保存即生效(新建任务时启用):

| 选项 | 前提 | 走谁的额度 | 说明 |
|---|---|---|---|
| 内置演示流程 | 无 | 不花钱 | 12 阶段演示,不产真实标书 |
| **自动(默认)** | 无——安装包已内置 OpenCode 1.18.13;本地运行包点「一键安装」按钮 | **我们的 token 套餐** | 只填一串我们发的 Key,点「测试连接」通过即可用。详见 `docs/让别人用S2模型.md` |
| **SoWork(商汤)** | 本机装好并登录 SoWork(自带 openclaw CLI,自动检测) | 本机 SoWork 账号 | 思考等级保持 off(S2 只支持 off) |
| **Claude Code** | 本机装好 [claude CLI](https://claude.com/claude-code) 并登录 | 你的 Claude 订阅 | 界面会显示 ✓/✗ 检测结果 |
| **Codex CLI** | 本机装好 codex CLI 并登录 | 你的 Codex 订阅 | 同上,由 codex 执行 |
| 自定义命令 | 任意本机 CLI agent | 看你接的啥 | 占位符:`{tender}` `{out}` `{materials}` `{jobid}` `{skill}`(**提示词里务必带上 `{skill}`,否则 agent 读不到技能包,输出质量会差一大截**) |

技能包已内置(首次运行自动解压到 `~/Documents/中标狗/bid-multiagent-tao`),不用手动装。

### 快速接入:两件事就够了

1. 粘贴我们发的 Key;
2. 选模式——**标准**(senseaudio-s2,写正式标书)或 **极速**(deepseek-v4-flash,试跑更快更省);
3. 点「一键接入并测试」——生成引擎、对话模型、识图模型全部自动配好,四步打勾即可用。

其余细项(换网关、单独指定生成模型、CLI 路径等)都在「高级」里,一般不用动。

### 给完全不懂技术的客户,话术就三句

1. 安装中标狗(见 `Mac安装说明.md`);
2. 打开中标狗 → 设置 → 把 Key 粘进快速接入卡 → 保持「**自动（默认）**」→ 点「一键接入并测试」;
3. 看到「✓ 连接成功」后,把招标文件拖进去就行。

(安装包已内置执行外壳;若用的是源码本地运行包,面板会出现「一键安装执行外壳」按钮,点一下即可。)

客户不需要理解 CLI、网关、协议这些词;「测试连接」失败时的提示都是中文的下一步动作。

## 四、sowork / workbuddy 平台内使用(不装桌面应用时)

SoWork 桌面版自带 openclaw CLI,**中标狗可以直接拉起它**(上表第 3 行),无需手工操作。
只有在"完全不装中标狗、纯在平台网页里跑"的场景才用技能包的「路径 B」手工流程:

1. 解压 `bidmultiagenttao_v5.3.zip`,把 `SKILL.md` 与 `references/角色提示词.md` 上传/粘贴到平台的 Agent 里
2. 按 SKILL.md「路径 B」的步骤,由主控 Agent 依序召唤各角色(命名照抄提示词里的规范表):前置分析 ×3 → 拆解 → 分章撰写 → 偏离表 → **主控亲自汇总**(平台不会自动做)→ 自检
3. 平台产出的 md 文件拿回本机,用 `references/build_tender_docx.py` 出 Word、`check_docx_format.py` 跑格式门禁(平台跑不了 python)

## 五、日常排查

- 引擎日志:`~/Documents/中标狗/engine.log`
- 任务与产物目录:`~/Documents/中标狗/jobs/<任务>/`
- 素材库:`~/Documents/中标狗/素材库/`(过往标书入库、图片、章节模板都在这)
- 从旧版升级时，应用会把 `~/Documents/标书助手` 的存量数据迁移到 `~/Documents/中标狗`，并固定从新目录读取；不需要手工复制历史任务或素材。

任务多时，「状态不明」和「已完成」分组默认收起，点分组标题即可展开或再次收起。要清理多条任务，点侧栏的「批量管理」后勾选任务，也可以全选/取消全选，再点「删除选中」；删除前只确认一次，结束后会分别显示成功数和失败数。

运行日志中的技能包状态有三种：

- **已验证使用**：当前 OpenCode 会话从首行到末行完整读取了技能清单，并由引擎签发了本轮证据；任务目录里的普通日志不能自行伪造该状态。
- **暂无法验证**：本轮没有足够运行日志可核对，**不等于未使用**，任务仍按实际出件结果判断。
- **未检测到**：本轮技能包没有完整装载、注入或被执行外壳接收；检查技能包路径及生成引擎注入，自定义命令需包含 `{skill}` 占位符。

## 六、遇到「获取失败」「一直是演示模式」怎么办(端口冲突)

v0.18.2 使用独立 WebView 会话和带版本号的入口地址，只连接**版本专属端口 18802**并校验精确引擎版本，不再读取旧页面缓存，也不回退 8849、8848 或 8080。覆盖安装时即使旧 PyInstaller 进程仍驻留，新 App 也不会把它误认成当前引擎。

如果界面顶部出现「**检测到旧版引擎占用端口**」横幅,说明当前连上的是一个旧引擎:

1. 完全退出旧版应用(Mac:⌘Q;Windows:任务栏右键退出),并结束遗留的引擎进程（正在生成的任务会中断，已落盘文件保留）:
   - macOS/Linux:`pkill -f bid-engine ; pkill -f engine_v1.py`
   - Windows(PowerShell):`Stop-Process -Name bid-engine -Force`
2. 重新打开最新版应用即可（状态栏应明确显示当前版本，例如「本地引擎 v0.18.2 · 已连接」）。

临时绕过:模型 ID 支持**手动输入**(如 `senseaudio-s2`),不依赖「获取模型列表」也能「添加并测试」。

## 七、提示「证书校验失败 / CERTIFICATE_VERIFY_FAILED」

打包版引擎不读系统钥匙串,缺根证书时会报这个错(与 Key、网关无关)。v0.9.3 起引擎会**先用系统/环境证书,失败自动回退到内置根证书(certifi)**,通常无需干预。

仍失败的两种情况:
- **公司网络代理拦截 HTTPS**:找 IT 要企业根证书装进系统,或临时勾选「跳过 HTTPS 证书校验」
- **内网自签名网关**:勾选「跳过 HTTPS 证书校验」(该项按接入点单独保存,仅影响这一个网关)
