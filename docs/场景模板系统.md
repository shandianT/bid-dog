# 场景模板系统

中标狗的模板不是固定目录或一段提示词，而是一份可校验、可版本化的“场景模板包”。它负责告诉生成流程如何组织、响应和检查，但永远不能覆盖本次招标文件原文。

## 六类内置场景

| 场景 | 重点设计 |
|---|---|
| 政府采购·综合 | 资格、符合性、实质性要求、评分索引、技术与商务偏离 |
| 政府采购·软件与信息化 | 总体架构、功能参数、实施迁移、安全合规、测试验收和运维 SLA |
| 设备与货物采购 | 核心产品、品牌型号、技术参数、供货安装、验收、质保和备件 |
| 工程施工与改造 | 施工组织、工期资源、质量安全、文明施工、项目机构和应急预案 |
| 运营、运维与综合服务 | 服务流程、人员班次、SLA、质量考核、应急和持续改进 |
| 咨询、规划与研究服务 | 问题理解、方法论、调研分析、里程碑、成果体系和专家团队 |

每个模板包包含：适用场景、建议目录、评分响应、标准表格、材料槽位、Word 格式、质检规则、来源与版本。创建任务时保存不可变快照，模板以后升级不会改变旧任务。

## 自动推荐

上传招标主件后，模板引擎从文件名、正文和 DOCX 表格内容中识别采购对象、采购方式、行业关键词、核心交付物和评分维度，返回推荐模板、命中依据和置信度。界面预览和真正建任务使用同一份主件与补充要求；识别不充分时固定使用综合模板并明确低置信度，不伪装成精确判断。

模板编译时遵守固定优先级：

1. 本次招标文件及正式澄清；
2. 用户确认的企业素材与补充要求；
3. 场景模板包；
4. 通用写作习惯。

## 从优秀历史标书生成模板

用户可上传自己有权使用的 `.docx`、可提取文字的 `.pdf`、`.md` 或 `.txt` 标书。系统执行：

1. 提取标题层级和可信表格首行；表格正文只短暂用于场景识别，不写入模板；
2. 根据全文特征推荐基础场景；
3. 把原始标题与字段泛化为章节、表格语义，移除单位、项目、人员和数值信息；
4. 合并基础场景的评分、材料与质检规则；
5. 生成质量评分和待审阅模板草稿；达到 4 个有效章节，或达到 2 个章节且至少有 1 个可信表格，才可保存；
6. 用户展开查看完整设计思路，并可修改模板名称和目录；确认后才保存到模板库。

模板草稿不保存正文段落或原始标题，不把客户名、报价、人员、证书内容或项目专属承诺带入新模板。源文件只记录脱敏名称和 SHA-256 指纹，用于本机去重与溯源。上传分析限制为 50MB；异常压缩的 Word 会在展开前拒绝。扫描版 PDF 需要先做 OCR 或另存为可提取文字的 Word。

## 质量与合规

- 招标文件与模板冲突时，以招标文件为准。
- 缺失材料标记为 `〔需补充〕`，不得猜测。
- 报价、投标人名称、资质有效期、承诺和签章必须人工确认。
- 公开模板优先参考政府部门发布的标准或示范文本，记录发布机构、版本和来源。
- 历史标书必须由用户确认拥有使用权；模板提炼不等于复制正文。
- 模板效果以评分点覆盖、材料缺口、返工率和质检结果衡量，不承诺中标。

## 当前验证口径

- 场景模板包完整性、推荐、脱敏、快照和浏览器保存闭环由离线测试覆盖。
- 固定工程样例的外部指令清单覆盖率从旧版 25% 提高到新版 91.7%；该指标只证明生成指令更完整。
- “标书最终质量更好”仍需在固定模型、固定素材和真实招标文件上持续比较评分点覆盖、事实无依据率、重复标题率与人工返工量，不能用模板字段的自覆盖率代替。

本次固定样例、盲评分数和后续真实验收方案见 [模板效果验证](模板效果验证.md)。
