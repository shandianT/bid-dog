技术架构

除了模型，一切都在用户电脑上

一单标书 = 6 段流水线
本地确定性 · 不花 token调用模型
  1. 环境准备连通 · 自检
  2. 招标解析本地解析 DOCX / PDF
  3. 响应规划评分点落到章节
  4. 并行撰写章节 4 路并发
  5. Word 装配确定性脚本出件
  6. 交付质检格式 · 覆盖 · 查重

架构上，除了模型，全部跑在用户电脑上：Tauri 桌面壳 + React 界面；中间是 FastAPI 本地引擎，打成单文件，用户不用装 Python；右边是可替换的执行外壳，默认内置 OpenCode，也能换 Codex、Claude Code。

下面 6 段流水线：蓝色本地确定性，不花 token；橙色才调模型。

多 Agent 编排

引擎当主控，每个 Agent 只干一件事

① 主控是代码，不是模型拆分、依赖、并发、重试都由引擎决定；Agent 只管写好自己那一段
② 文件即接口只读声明的输入、只写声明的输出；校验通过才交给下一棒
③ 上下文不串台每个 Agent 独立短会话，只喂本章评分点和相关素材

多 Agent 怎么编排？一句话：引擎当主控，每个 Agent 只干一件事。

本地先解析招标文件；规划 Agent 拆出组成、评分点、废标项，输出一张带依赖的章节图；（可选）人工确认关键信息后，撰写 Agent 按章并行，偏离表也各由一个 Agent 负责——最多 4 路同时在飞，写完一章立刻补位。

汇总交给本地脚本；标准模式再加一个复核 Agent，挑出必办问题，一键只重写那一章。Agent 之间不聊天，只通过文件交接，校验通过才交给下一棒。

核心工程 · Harness Engineering

给模型套上缰绳：Agent = 模型 + Harness

模型负责写；Harness 负责让结果稳定、可验证、可交付

1约束Guide
只给恰好够用的上下文
  • 场景模板 + 章节撰写契约
  • 素材按章检索，评分点落到本章
  • 传入已用小标题，防跨章重复
2隔离Sandbox
最小权限，边界改不了
  • 每个节点独立目录，只给声明输入
  • 禁 shell / 子 agent / 联网 / 越界
  • 真 Key 不给外壳，只给本机口令
3验证Verify
只信证据，不信模型自报“完成”
  • 产物存在且校验通过，才算完成
  • 进度事件 HMAC 签名，agent 伪造不了
  • 质检 0 token，拦截模型复读循环
4恢复Recover
断了只重跑一个节点
  • 检查点 pipeline.json 原子落盘
  • 退避重试 8s → 240s，停滞自动判定
  • 撞 429 限流，并发 4 路自动降 2 路
5评测 Eval500+ 项离线回归（假上游 · 假外壳 · 卡死 agent 故障注入）· 模型 A/B 跑批 · 用量逐次记账全绿才出包 ✓

Agent 跑起来不难，难的是稳定、可交付——这靠模型外面那层工程：Harness。四层：

约束，只给恰好够用的上下文；隔离，节点跑在沙箱，禁 shell、禁联网，真 Key 不给外壳；

验证，不信模型说“做完了”，只认磁盘上的产物，进度事件 HMAC 签名，质检是确定性脚本；恢复，检查点落盘，断了只重跑那一个节点。

最后，500 多项离线回归 + 模型 A/B，全绿才出包。
