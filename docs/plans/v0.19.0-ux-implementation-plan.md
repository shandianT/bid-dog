# v0.19.0 结果优先体验实施计划

## 目标

在不破坏历史任务和 v0.18.2 稳定性闸门的前提下，实现任务契约中的结果优先体验，并用后端契约、浏览器行为和桌面构建三层证据验收。

## 方案

后端提供统一的 `presentation / capabilities / delivery / usage` 视图，前端不再自行猜测内部状态。任务目录仍是唯一持久化来源，新增元数据字段采用向后兼容的惰性迁移。前端按“任务列表—任务工作区—交付结果—诊断详情”四层信息架构重排；技术细节只进入诊断层。

## 步骤

1. 在 `tests/` 先补失败契约测试：五态映射、回退文案/诊断分离、能力标志、归档恢复、批量语义、交付摘要、诊断与指标。
2. 在 `server/engine_v1.py` 增加稳定展示模型、归档/项目/模板/修订元数据、批量接口、一键诊断、用量视图和有界自动恢复；所有写操作沿用 owner/control 互斥。
3. 在 `app/src/index.html` 重做任务列表状态、批量操作、新建任务三步向导、交付结果首屏、诊断抽屉、模板与继续修改入口；所有错误给出明确动作。
4. 在 `app/src-tauri/src/main.rs` 和 capabilities 中补系统通知、关闭行为与后台任务语义；在 CI 中增加可选签名/公证配置检查。
5. 将同一前端同步到 `site/demo.html`、`site/app/index.html`，更新网站、README、CHANGELOG 和版本号。
6. 依次运行 Python、Node、Chromium、Tauri/sidecar 构建验证；对失败执行红—绿—重构闭环。

## 风险与未知

- 单文件前端体积大，采用纯函数和后端展示契约减少状态分叉，不在本次强行引入框架迁移。
- OpenCode 探活重试不能把首单等待翻倍；采用总时限内的一次干净恢复和立即 CLI 回退。
- 费用取决于上游是否返回 usage；没有 token/价格数据时只显示用时和“费用暂不可估算”。
- Apple 公证和 Windows 商业签名需要外部证书与 CI secrets；代码与工作流可准备就绪，但不能伪造签名完成。
- 真正“退出应用后继续运行”需要引擎生命周期脱离窗口但仍可控；先确保关闭窗口不杀任务，再验证系统托盘/再次打开的恢复路径。

- 逐项对照 `v0.19.0-ux-product-contract.md` 的 acceptance 块，不以测试总数代替需求覆盖审计。
