# v0.19.0 结果优先体验任务契约

## 目标

把中标狗从“能运行的标书 Agent 控制台”改造成普通投标人员不需要理解技术架构也能完成工作的产品：首次使用只需填写 Key、测试连接、上传文件；运行中只看到可理解的状态、当前动作、最近活动和预计时间；结束后第一屏直接得到可交付 Word、目录/偏差表/关键门禁结论及下一步动作。

## 素材与现状

- 当前 v0.18.2 已具备任务创建、OpenCode server/CLI 回退、暂停/停止、SSE、质量门禁、产物打开、批量删除和桌面安装包。
- 前端是 `app/src/index.html` 单文件应用，并同步到 `site/demo.html` 与 `site/app/index.html`。
- 后端是 `server/engine_v1.py`，任务数据按目录保存，必须兼容历史任务。
- 桌面壳使用 Tauri，macOS 当前仅 ad-hoc 签名，Windows 当前未配置商业代码签名。

## 高杠杆标准

1. 用户界面只有“准备中、生成中、需要你确认、已完成、未完成”五种任务状态；历史 `unknown/stopped/paused/running/done/staged` 只作为内部状态。
2. 每个任务都能给出当前动作、最近活动时间、预计剩余时间和当前可用能力；缺少证据时明确显示“正在估算”，不伪造时间。
3. server 探活失败、重试和 CLI 回退由系统处理。主界面只显示“连接响应较慢，已自动切换稳定模式，任务正在继续”；技术原因写入诊断详情。
4. 稳定模式不支持暂停/原会话继续时，按钮必须禁用并解释影响，不能让用户点后才失败。
5. 完成页第一屏以主 Word 为核心，同时显示目录、偏差表、关键检查和明确动作；日志和引擎信息移入诊断层。
6. 归档是任务整理的主动作；删除进入二级危险操作。支持批量归档、恢复、重跑、导出，并能按项目筛选/归类。
7. 首次使用只有三步：Key、连接测试、上传文件。引擎、CLI 路径、模式和模型默认自动选择，高级设置不阻塞首单。
8. 支持模板、基于当前交付物继续修改、用时/估算费用/调用量、明确错误动作、一键诊断和完成通知。
9. 应用窗口关闭不应杀掉仍在运行的任务；后台引擎完成后能在桌面应用仍运行时发系统通知。
10. 历史任务、历史配置和现有自动化不能丢失或静默改变语义。

## 约束与失败处理

- 不把 Key、令牌、完整网关响应或用户文件内容写入前端、日志包、测试夹具或 Git。
- 不以“没有报错”代替验收；完成仍必须有磁盘上的正文 Word 证据。
- 批量操作逐项隔离失败、只确认一次、只刷新一次并返回可读汇总。
- 费用只能标记为“估算”；缺少 token/价格依据时显示不可估算，禁止编造精确金额。
- Apple 公证和 Windows 商业签名只有在 CI 凭据存在时执行；凭据缺失时构建仍可验证，但发布说明必须如实标注。
- 任何外部证书、账号或商业权限缺失都不能阻止其余体验功能继续完成。

## 反例

- 主界面出现“执行外壳探活失败、SSE、CLI、fingerprint、HTTP 502”等技术文本。
- 列表出现“状态不明”，或任务只显示百分比而没有最近活动/当前动作。
- 回退后仍显示可暂停按钮，点击才告诉用户不支持。
- 完成页先展示聊天和日志，需要用户自己从十几个文件中猜最终 Word。
- 只有批量删除，没有归档/恢复；或批量重跑重复弹出 N 次确认。
- 首次启动先让用户选择 OpenCode/Codex/CLI 路径、模型协议和运行模式。

> 已完成 · 最终 Word 可交付 · 目录已生成 · 偏差表完整 · 关键检查通过

version: 0.19.0
asserts:
  - api.jobs[].presentation.state in [preparing, generating, needs_input, completed, incomplete]
  - api.jobs[].presentation has [label, current_action, last_activity_at, eta]
  - api.jobs[].capabilities has [can_pause, can_resume, can_modify, can_archive, can_export]
  - fallback_user_message == "连接响应较慢，已自动切换稳定模式，任务正在继续。"

  - completed requires a valid body Word artifact
  - result_summary has [primary_word, directory, deviation_table, critical_checks]

  - batch actions include [archive, restore, rerun, export]
  - onboarding steps == [key, connection_test, upload]
  - diagnostic checks include [version, engine, key, model, storage]
  - technical terms are absent from primary user-facing status copy
  - desktop, demo, and hosted app frontends are byte-identical
  - secrets are absent from repository and diagnostic payloads
tests:
  - python backend contract and migration tests
  - node pure-function and source contract tests
  - chromium onboarding, task-list, result-center, batch-action, and recovery tests
  - tauri build configuration and sidecar smoke tests
