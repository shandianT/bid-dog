# 让别人用 S2 模型（默认 OpenCode 执行外壳）

> 目标：把中标狗发给同事或客户。他们不需要 Claude / Codex 订阅，不需要安装 Node.js，也不用登录 AI 账号；只填一串发放的 Key，就能用 S2 模型生成标书，额度记在发放方的 token 套餐上。
> 作者：FDE-家涛

---

## 一、v0.18.0 的默认链路

v0.18.0 起，「自动（默认）」生成引擎使用安装包内置的 **OpenCode 1.18.13**。OpenCode 原生支持 OpenAI 兼容的 `chat/completions`，不再需要旧版 Codex 的 Responses ↔ Chat 协议翻译。

```text
OpenCode ──OpenAI 兼容请求──▶ 中标狗本地引擎 /v1/relay/chat/completions ──▶ S2 网关
   │                              │
   └─ 读招标文件、调用技能包、      └─ 校验本机中转口令，真 Key 仅在引擎进程内使用
      写文件、执行出件与质检脚本
```

选择 OpenCode 的原因不是换模型，而是换执行外壳：在同一份真实招标文件、同一模型、同一素材和同一提示词的对比中，OpenCode 的分章子 agent 能更完整地覆盖评分项、偏离表和废标风险。详细数据见根目录 [CHANGELOG.md](../CHANGELOG.md#0180---2026-08-06)。

Codex CLI 仍保留为设置中的显式选项。选择 Codex 时使用客户自己的 Codex 登录态和订阅，不会注入 S2 Key，也不会改写客户原有的 `~/.codex`。

## 二、客户怎么用（三步）

1. 从 [GitHub Releases](https://github.com/shandianT/bid-dog/releases/latest) 下载并安装中标狗。macOS 若提示无法打开，见 [Mac 安装说明](Mac安装说明.md)。
2. 打开「设置 · 模型接入」，把收到的 `sk-…` Key 粘进最上面的快速接入卡，选择「标准」或「极速」。
3. 点「一键接入并测试」。四步均显示通过后，把招标文件拖进窗口即可。

正式安装包已经内置 OpenCode，客户不需要安装 Node.js，也不用执行命令。源码本地运行包如果没有外壳，面板会显示「一键安装执行外壳（下载约 60MB）」；解压后约 170MB。也可手动执行：

```bash
npm i -g opencode-ai
```

网关地址和模型名留空时使用应用内默认值；需要切换其他 OpenAI 兼容网关时再展开高级设置修改。

## 三、Key 怎么发

建议一人一 Key，不要多人长期共用同一串：

- 额度和并发可分别统计；
- 某个 Key 泄漏时可单独停用；
- 出现 401、429 或异常消耗时能定位到具体使用者。

| 方式 | 适用场景 | 说明 |
|---|---|---|
| 手动发 Key | 内部同事、少量客户 | 在网关后台创建子 Key，通过可信渠道单独发送 |
| 客户专属预置包 | 某一家客户的定制交付 | 通过 `preset_config.json` 首次写入；公开发布包严禁携带任何真实 Key |
| 激活码换 Key | 用户量较大 | 由自建服务按激活码发放子 Key；规模化后再建设 |

客户专属 `preset_config.json` 示例：

```json
{
  "providers": [],
  "routing": {},
  "engine": {
    "kind": "s2",
    "mode": "agents",
    "s2_base_url": "https://api.senseaudio.cn/v1",
    "s2_model": "senseaudio-s2",
    "s2_key": "sk-仅用于该客户的Key"
  }
}
```

该文件只在首次启动且本机尚无配置时生效，不覆盖老用户配置。

## 四、安全边界

- 快速接入卡保存的 S2 Key 不会通过 `/v1/agent` 回传给页面；接口只返回是否已填写。
- 默认链路中，OpenCode 拿到的是本机随机中转口令，真 Key 只由中标狗引擎向上游网关发送。
- 中转端点仅监听 `127.0.0.1`，并校验本机中转口令。
- OpenCode 配置写入中标狗数据目录下的 `opencode_s2/`，并使用独立的 `OPENCODE_CONFIG`、`XDG_DATA_HOME`、`XDG_CONFIG_HOME` 和 `XDG_CACHE_HOME`，不读取或覆盖用户自己的 OpenCode 配置。
- 默认禁止 OpenCode 的 `webfetch`，标书事实只允许来自招标文件和素材库；素材库与技能包位于任务目录外，因此 `external_directory` 被显式放行，避免非交互任务永久等待授权。
- 公开仓库、Issue、群聊和日志中都不要粘贴真实 Key、客户证照、报价或完整涉密标书。

## 五、额度怎么计算

| 使用方式 | 走谁的额度 |
|---|---|
| 「自动（默认）」+ 发放的 Key | 发放方的 token 套餐；OpenCode 只负责本地执行 |
| 显式选择 Codex CLI | 客户自己的 Codex 登录态和订阅 |
| 显式选择 Claude Code | 客户自己的 Claude 登录态和订阅 |
| 选择 SoWork | 本机已登录的 SoWork 账号 |

「标准 / 极速」是发放 Key 路径的模型选择；切到 Codex、Claude 或 SoWork 后，这两个模式不会改变外部 CLI 的订阅。

## 六、测试连接失败时

| 提示 | 原因 | 处理方式 |
|---|---|---|
| 还没填 API Key | 快速接入卡和接入点都没有可借用的 Key | 填入发放的 Key |
| Key 不对或已停用 | 网关返回 401 | 换一串有效 Key |
| Key 没有权限 | 网关返回 403 | 检查该 Key 的模型/项目权限 |
| 额度/频率超限 | 网关返回 429 | 检查套餐余额与并发限制 |
| 套餐里没有模型「x」 | Key 有效，但模型不在可用列表 | 按提示选择一个可用模型 |
| 只差执行外壳 | 本地运行包未安装 OpenCode | 点「一键安装」，或执行 `npm i -g opencode-ai` |
| 生成 OpenCode 配置失败 | 数据目录不可写或被安全软件拦截 | 检查「文稿/中标狗」目录权限后重试 |
| Unexpected server error | 本机回环连接或上游网关异常 | 确认安全软件未阻止 `127.0.0.1`，再点测试连接 |

安装包内置外壳会在 CI 中实际运行 `opencode --version`。Windows x64 固定使用 baseline 变体，以兼容不支持 AVX2 的旧 CPU。

- [ ] macOS 与 Windows 安装包内均包含 `bid-engine` 和 `opencode-cli`
- [ ] 内置 OpenCode `--version` 返回 1.18.13
- [ ] 「自动（默认）」显示执行外壳已内置，不出现误报缺失
- [ ] 没填 Key 时明确进入演示流程；填 Key 后三层测试均通过
- [ ] OpenCode 配置生成失败时任务不会启动，也不会回落到用户个人配置
- [ ] 显式选择 Codex 时保留用户自己的 `~/.codex` 登录态
- [ ] 素材库、技能包和任务目录均可访问，不出现 `external_directory: ask` 挂起
- [ ] 真实招标文件能生成 `.docx`，并通过格式门禁与成品质检
- [ ] 公开发布包和仓库中不含 `preset_config.json`、真实 Key 或客户数据
