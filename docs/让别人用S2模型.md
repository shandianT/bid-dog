# 让别人用 S2 模型(走我们的 token 套餐)

> 目标:把中标狗发给同事/客户,他们**不需要 Claude 账号、不需要 Codex 订阅、不需要装 SoWork、不需要登录任何东西**,
> 只填一串我们发的 Key,就能用 S2 模型产标书,额度记在我们的 token 套餐上。
> 作者:FDE-家涛

---

## 一、结论先说:Codex 能不能直接接我们的 S2?

**能,但不能"直接"。** 这是实测出来的结论(codex-cli 0.146.0):

| 问题 | 实测结果 |
| --- | --- |
| Codex 支持自定义模型供应商吗? | ✅ 支持。`CODEX_HOME/config.toml` 里写 `[model_providers.xxx]`(`base_url` + `env_key`),用 `model_provider` 选中即可。请求会带 `Authorization: Bearer $env_key` 打到 `{base_url}/responses`。 |
| 能让它走 `/chat/completions` 吗? | ❌ **不能了。** `wire_api = "chat"` 已被移除,填了直接报错退出:<br>`` `wire_api = "chat"` is no longer supported. How to fix: set `wire_api = "responses"` `` |
| 那我们的 S2 网关呢? | 只有 `/v1/chat/completions`(OpenAI **chat** 兼容),没有 `/v1/responses`。 |

所以两边差的**只是一层协议翻译**——不是"要重做一套桥",而是"把 Responses 请求翻成 chat/completions 再翻回来"。

这层翻译我们放进了**已经随 App 一起分发的那个本地引擎**里:
不多装一个进程、不多开一个端口、不改客户机器上原有的 `~/.codex`。客户那边只是多填一个 Key。

```
Codex CLI ──Responses──▶ 中标狗引擎 /v1/relay ──chat/completions──▶ 你的 S2 网关
   (执行外壳:                (翻译 + 你的 Key            (api.senseaudio.cn)
    跑命令/写文件/读技能包)     只在这一层出现)
```

**为什么还要 Codex,不自己写 agent 循环?**
因为出标书要真的读 PDF、跑 `build_tender_docx.py`、写文件、自检返工——这些"手脚"Codex 已经做得很好,
而且你现在的 codex 引擎本来就是通的。我们只换掉它背后的"大脑",不重写手脚,改动面最小、回退最容易。

## 二、客户那边要做什么(两步,三分钟)

1. **装中标狗**:下载 dmg / exe 安装(macOS 提示"已损坏"见 `docs/Mac安装说明.md`)。
   **v0.12.1 起安装包已内置执行外壳(Codex 二进制)**,不用装 Node、不用跑任何命令。
2. **填 Key**:打开中标狗 → 设置 · 模型接入 → 生成引擎 → 选 **「S2 模型 · 用我们发的 Key」**
   → 粘贴我们发给他的 `sk-…` → 点 **测试连接** → 看到「✓ 连接成功」就能用了。

用**本地运行包**(zip 源码版)的人没有内置外壳,面板里会出现
**「一键安装执行外壳(约 130MB)」**按钮,点一下自动下载(国内走 npmmirror 镜像,失败自动换官源,带进度);
装过 Node 的也可以手动 `npm i -g @openai/codex`。三条路殊途同归,都不需要登录。

网关地址和模型名留空即可(默认 `https://api.senseaudio.cn/v1` + `senseaudio-s2`);
要换成别的兼容网关就填上去。

## 三、Key 怎么发(重要)

**一人一 Key,不要所有人共用一串。** 理由:

- 额度能分开看、能单独停;
- 谁泄漏了只废他那一串,不用全员换;
- 出问题能定位到人。

发放方式按成本从低到高:

| 方式 | 适合 | 说明 |
| --- | --- | --- |
| 手动发 Key | 内部同事、几个客户 | 在你的网关后台建子 Key,微信/邮件发给他,他填进设置里。最省事。 |
| 预置到安装包 | 给某一家客户的定制版 | 把 `preset_config.json` 放在引擎旁边(或设 `BID_PRESET` 指向它),首次启动自动作为配置种子——客户连 Key 都不用填。**只在专供某客户的构建里做**,公开发布包严禁携带。已有配置的老用户绝不会被覆盖。 |
| 自建发号接口 | 上规模了再说 | 客户填"激活码"→ 你的服务换成真 Key。当前阶段不建议,收益不抵复杂度。 |

`preset_config.json` 示例(定制包用):

```json
{
 "providers": [],
 "routing": {},
 "engine": {
   "kind": "s2",
   "mode": "agents",
   "s2_base_url": "https://api.senseaudio.cn/v1",
   "s2_model": "senseaudio-s2",
   "s2_key": "sk-发给这家客户的Key"
 }
}
```

**Key 的安全边界(已经在代码里保证了):**

- Key 存在客户本机的引擎配置里,**页面从不回显**(`/v1/agent` 只回 `s2_key_set: true/false`)。
- 真 Key **不进 Codex 的环境变量**:给 Codex 的是一串本机随机中转口令,真 Key 只在引擎进程内使用。
- 中转端点只听 `127.0.0.1`,且校验中转口令——同机的其他程序拿不到你的额度。
- 生成的 Codex 配置写在中标狗自己的数据目录(`~/Documents/中标狗/codex_s2/`),
  **客户原有的 `~/.codex` 登录态和订阅额度一个字都不动**。

## 四、两种额度别搞混

| | 走谁的钱 | 什么时候用 |
| --- | --- | --- |
| **S2 引擎(本文)** | **我们的 token 套餐**(那串 Key) | 发给同事/客户用 |
| Codex CLI 引擎 | 客户自己的 Codex 订阅 | 他自己有订阅、想用 GPT 系模型 |
| Claude Code 引擎 | 客户自己的 Claude 订阅 | 同上 |
| SoWork 引擎 | 他本机 SoWork 登录的账号 | 公司内已铺了 SoWork |
| 「模型接入」里的 Key | 那个 Key 的额度 | 只管**对话/识图**,不管生成标书 |

## 五、连不上时怎么排查

点「测试连接」,它是**分三层报的**,照着那一层修就行:

| 提示 | 意思 | 怎么办 |
| --- | --- | --- |
| 还没填 S2 API Key | 没填,也没有可借用的接入点 | 填 Key |
| 连不上 S2 网关:Key 不对或已停用 | 网关回 401 | 换一串新的 Key |
| 连不上 S2 网关:Key 的额度/频率超限 | 网关回 429 | 套餐用完了,或并发太高 |
| 网关通了,但你的套餐里没有模型「x」 | Key 有效但模型不在套餐 | 按提示里列出的可用模型改 |
| S2 网关是通的,只差执行外壳 | 缺执行外壳 | 点面板里的**一键安装**按钮(或 `npm i -g @openai/codex`) |
| 退出码 N · 中转层报告:… | 前两层都通,卡在真实调用 | 按中转层给的原因处理 |

还想看细节:`GET http://127.0.0.1:8848/v1/relay/status` 会回最近一次中转的模型、消息数、
工具数、被丢弃的工具类型、token 用量和错误原文。

## 六、已知取舍

- **`web_search` 用不了。** Codex 的联网搜索是 OpenAI 网关侧的内建工具,chat 协议里没有对应位置,
  中转时会丢掉(`relay/status` 的 `dropped_tools` 会如实列出)。写标书基本用不到,需要时改用素材库。
- **思考过程不透传。** 上游的 `reasoning_content` 不转发给 Codex(它本来就 `hide_agent_reasoning`),
  少一类协议噪声。
- **模型元数据告警。** Codex 会提示 `Model metadata for senseaudio-s2 not found`,是它不认识这个模型名而已,
  不影响运行。
- **效果取决于 S2 的工具调用能力。** 中转只保证协议对得上;S2 能不能稳定按工具协议干活,
  要用真实招标文件跑一轮才算数——第一次给客户前,自己先跑一份。
- **将来 S2 网关补上 `/v1/responses` 的话**,把「生成引擎」里的 `s2_wire` 设成 `responses` 即可直通,
  中转层自动让路,一行代码都不用改。

## 七、给我们自己的验收清单

发版前必跑(都已在 0.12.0 实测通过):

- [x] Codex → 中转 → 只有 chat/completions 的网关,**工具调用真的落盘**(模型让它写文件,文件确实出现)
- [x] 多轮闭环:`function_call` → `function_call_output` → 第二轮带着 `tool` 消息回到上游
- [x] 命名空间工具(子 agent 那一组)摊平成普通函数,不会漏
- [x] 没 Key / 网关不通 / 模型不在套餐 / 没装 Codex —— 四种失败都给出能自己解决的中文
- [x] 生成的 `config.toml` 指向独立 CODEX_HOME,不碰客户的 `~/.codex`
- [x] 控制台没有 `OutputTextDelta without active item` 这类协议告警
- [x] 一键安装:下载→解压→校验→resolve 立刻用上;重复点幂等;文件损坏自动重下(12 项专测)
- [x] 安装包内置外壳优先于 PATH 里客户自己装的版本(版本钉死 0.146.0,与中转实测配套)
- [x] 预置配置只在首启无配置时种入,老用户配置绝不覆盖
