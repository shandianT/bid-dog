# 生成流程台与断线恢复设计

## 目标

让客户在 Windows 首次生成、网络短暂中断或本地组件修复期间，始终能看懂“正在做什么、做到哪里、最后完成了什么、断线后如何继续”。界面展示必须来自任务目录中的持久化事实，不能用纯动画或估算百分比伪装真实进展。

## 设计原则

1. **六段流程，一眼能懂。** 将现有 12 个执行阶段归并为环境准备、招标解析、响应规划、并行撰写、Word 装配、交付质检六个宏观阶段。
2. **事实与连接状态分离。** 任务进展取自 `preflight.json`、`progress.json`、`events.jsonl` 和产物文件；浏览器是否连上事件流只影响“实时/轮询”提示，不改变任务状态。
3. **先保命，再提速。** 第一步先验证数据目录、技能包、执行引擎和模型连接。缺组件自动修复，失败停在可恢复检查点，不进入正文流程。
4. **断线不等于任务停止。** 实时事件流失败后自动重连；连续失败则启用任务列表轮询兜底。恢复连接后继续使用事件偏移量，不重复创建任务。
5. **路径可解释。** 桌面安装版只使用随安装包交付的 sidecar 和应用数据目录；不依赖客户安装 Python、Node、Codex 或 SoWork。诊断信息展示经过脱敏的路径来源和组件版本。

## 用户界面

任务过程页新增紧凑的“生成流程台”，位于当前对话和工作记录之前，不采用占满页面的大型 DAG。

### 顶部状态

- 当前动作，例如“正在检查生成组件”或“正在汇总成册”。
- 最近检查点，例如“已完成：评分项与废标条件提取”。
- 连接状态：实时连接、正在重连、轮询保障中、连接已恢复。
- 最近活动时间；超过阈值时提示“暂时没有新进展，任务仍在后台运行”，不直接宣判任务失败。

### 六个宏观阶段

| 阶段 | 对应现有步骤 | 可见证据 |
|---|---:|---|
| 环境准备 | 0 | 存储、技能、运行时、模型连接检查 |
| 招标解析 | 1–4 | 文件体检、图片清单、结构和格式提取 |
| 响应规划 | 5–6 | 评分/废标索引、分工计划 |
| 并行撰写 | 7–8 | 章节草稿、逐条响应矩阵 |
| Word 装配 | 9–10 | 汇总稿、插图复核、Word 草稿 |
| 交付质检 | 11–12 | 自检报告、最终 Word 与格式报告 |

每个阶段只有 `待执行`、`进行中`、`已完成`、`需处理`、`失败` 五种状态。当前阶段展开一条具体动作和证据；环境阶段可展开四个子检查，避免用户只看到“第 1 步卡住”。

## 后端状态合同

`GET /v1/jobs` 为每个任务补充 `flow`：

```json
{
  "version": 1,
  "current_phase": "environment",
  "current_action": "正在检查生成组件",
  "checkpoint": {"step": 0, "label": "任务文件已保存"},
  "recoverable": true,
  "phases": [
    {
      "id": "environment",
      "label": "环境准备",
      "state": "active",
      "detail": "正在验证本地执行引擎",
      "evidence": "preflight.json",
      "checks": []
    }
  ]
}
```

`flow` 由任务目录的持久化状态确定性计算，不新建第二套进度数据库。无状态或旧任务也必须得到兼容结果。失败任务保留最后已验证检查点；只要任务目录与检查点存在，就标记为可恢复。

## 断线恢复状态机

1. EventSource 打开：显示“实时连接”，重置失败次数并停止轮询。
2. EventSource 异常：记录失败次数，按 3、4、6、10 秒上限退避重连。
3. 连续 3 次异常：同时开启每 4 秒一次的 `/v1/jobs` 轮询，显示“轮询保障中”。
4. EventSource 恢复：使用现有事件偏移继续读取，停止轮询并短暂显示“连接已恢复”。
5. 页面切后台再回来：刷新任务持久化状态并重建事件连接。
6. 切换任务或归档任务：关闭旧 EventSource、重连计时器与轮询计时器，防止重复连接。

轮询只更新展示，不启动或重启任务。重跑、继续做和重试 Word 仍由用户显式操作。

## 环境与路径适配

- Tauri 从可执行文件同目录及打包资源目录确定性寻找 `bid-engine`，失败写入 `engine-bootstrap.log`。
- Python sidecar 内置所有运行依赖；OpenCode 使用固定版本、应用数据目录和校验后的可执行文件。
- 路径拼接统一使用平台路径 API，测试覆盖中文、空格和 Windows 风格路径。
- 源码一键启动脚本可按需安装依赖；桌面安装包不在客户运行时安装 Python 包。
- 诊断包包含组件版本、候选路径来源、最后检查点和脱敏错误，不包含密钥或客户正文。

## 验收标准

1. 新任务在正文第 1 步前展示环境准备子检查，用户能区分路径、依赖、引擎和连接问题。
2. 六段流程状态与现有 12 阶段及磁盘证据一致；刷新页面后不丢失。
3. 连续三次事件流失败后自动进入轮询保障，任务进度仍可更新；恢复后回到实时连接。
4. 断线、刷新和切换任务不会重复创建任务或重复连接。
5. 失败任务显示最后检查点和可恢复性，不把“没有前端连接”误报成“任务停止”。
6. Windows 中文和空格安装路径能定位 sidecar；新环境缺组件时能自动修复或给出明确诊断。
7. 后端、前端静态、浏览器、Rust 和最终 macOS/Windows 安装包烟测全部通过后才发布。
